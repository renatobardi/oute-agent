Regras desta sessão (rodada {{ID}}, issue #{{N}}; fase `build` do AI-DLC, ADR-07):
- Você está numa worktree própria. Leia `AGENTS.md`/`CONTEXT.md` do repo e `gh issue view {{N}}` antes de mexer.
- Mexa só no necessário para a issue #{{N}}. Outras sessões trabalham em paralelo em outras áreas; não toque nelas.
- Antes de abrir o PR, liste os ramos de erro ou de estado que o seu PR cria (código de retorno, quarentena, descarte, laço de retentativa, fallback) e confira que cada um tem pelo menos um teste em `tests/`. O ramo que ficar sem teste vai para o corpo do PR, com o motivo.
- Antes de abrir o PR, rode cada teste novo ou alterado em dois ambientes: o da sessão e um limpo (`env -i HOME="$(mktemp -d)" PATH="$PATH" LANG=C.UTF-8 bash tests/<x>.test.sh`). Se o resultado difere entre os dois, o teste depende do ambiente: corrija o teste, não o ambiente. Teste que executa script do host (`scripts/oute` e afins) tira do ambiente as credenciais reais que o script usaria (`OCI_S3_*`, `GH_TOKEN`, `AGENT_STUDIO_*`…), para nunca chegar a recurso de verdade.
- Antes de abrir o PR, rode cada teste novo ou alterado que prova um critério contra o código da `main` (os testes do branch com o código da base: `git worktree add` da `origin/main` + `git checkout <branch> -- <testes>`, ou a correção desfeita): o caso tem que falhar. O corpo do PR diz quais casos falharam assim; critério cuja prova não falha sem a correção não leva `[x]`. É o que a `oute-aidlc-qa-pr-audit` confere no passo 6.
- Antes do push, renomeie o branch para `<tipo>/{{N}}-<slug>` (feat, fix, chore, docs…). Entregue por PR. No corpo do PR: `Closes #{{N}}` **só se o PR cumpre todos os critérios de aceite da issue**. Senão `Refs #{{N}}` e uma seção `## Falta` listando o que ficou de fora. O critério de pós-deploy (fase `ship`: só se verifica depois da release e do deploy nos hosts) não conta para `Closes` × `Refs`: liste-o no `## Falta` com a marca `(ship)`.
- Ações no host: só pelo canal de aprovação (`oute-propose`, depois `oute-inbox --wait <id>`). Nunca peça ao Bardi para copiar comando. Antes do merge do seu PR, pelo canal só **diagnóstico e dry-run** (`--dry-run`, `--check`, leitura). Aplicar mudança no host só **depois do merge**, quando o dispatcher ou o Bardi pedir. Se a issue exige aplicar, termine com `PRONTO #{{N}}: <url do PR> — aplicar no host depois do merge` e espere.
- **Não faça merge.** Quando o PR estiver aberto e o CI verde, termine com uma linha `PRONTO #{{N}}: <url do PR>`. Se precisar de decisão, termine com `BLOQUEADO #{{N}}: <pergunta>`.
