- Before opening the PR, list the error or state branches your PR creates (return, quarantine, discard, retry, fallback) and check each has at least one test in `tests/`. A branch left without a test goes in the PR body, with the reason.
- Before opening the PR, run each new or changed test:
  - in two environments: the session's and a clean one (`env -i HOME="$(mktemp -d)" PATH="$PATH" LANG=C.UTF-8 bash tests/<x>.test.sh`). If the result differs, the test depends on the environment: fix the test, not the environment;
  - if it starts a background process (server, receiver, database), 3 times in a row, all green (`(for i in 1 2 3; do bash tests/<x>.test.sh || { echo "falhou na execução $i" >&2; exit 1; }; done)`; `|| break` would exit 0 even on failure). Whatever stays flaky goes in the PR body, with the case and the error;
  - if it runs a host script (`scripts/oute` and the like), remove from the environment the real credentials the script would use (`OCI_S3_*`, `GH_TOKEN`, `AGENT_STUDIO_*`…);
  - if the PR changes `tests/*.test.sh` or `tests/lib/`, also run `bash tests/check-lib.test.sh` (session and clean environments) and say in the PR body that you ran it: it is the `check` lint (#285), and a failure there is a PR failure (#401); also run `bash tests/parallel-lib.test.sh` (session and clean environments) to check tests that start background services, and say in the PR body that you ran it;
  - if it proves a criterion, run it against the `main` code (the branch's tests with the base code: `git worktree add` of `origin/main` + `git checkout <branch> -- <testes>`, or the fix reverted): the case must fail. The PR body says which cases failed this way; a criterion whose proof does not fail without the fix gets no `[x]` (`oute-aidlc-qa-pr-audit`, step 6).
- A new or changed test must not depend on a value that changes on every run:
  - **Clock:** a relative date or age keeps a margin from the limit the code checks, or the clock is pinned; never at the exact limit. E.g.: the code rejects `age > 7` days → cases with 6 and 9 days, not "now − 8 days".
  - **Random name:** what the test looks for in the output, or asserts is absent, must not match a piece of a `mktemp` path or of another random name: check the whole name. E.g.: `! grep -q 'b1'` fails with `/tmp/tmp.Xb1k…`; use `! grep -qF "$SP/proj-b1"` (or `grep -qx`).
- **In tests and scripts, `rm` with a variable uses `"${VAR:?}"/…` or a literal path**, so it does not trigger the permission prompt. E.g.: `rm -f "${FAKE:?}"/*.json`. Without it, Claude Code asks for permission and, with no answer, denies the command in ~1 min 35 s (#358).
- Before writing in a doc, ADR or PR body that a value, command, variable or file "was removed", "is no longer emitted" or "is no longer used", check with `git grep -n -e '<termo>'` on the whole repo, from the root, with no folder filter. The PR body cites the command and the result: the empty output, or each remaining occurrence and why it stays. With a live occurrence in code, the statement does not hold: write what changed (who stopped emitting and who still does).
