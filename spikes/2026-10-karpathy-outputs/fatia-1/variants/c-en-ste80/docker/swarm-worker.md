Rules for this session (rodada {{ID}}, issue #{{N}}; phase `build` of the AI-DLC, ADR-07):
- You are in your own worktree. Before you change anything, read `AGENTS.md`/`CONTEXT.md` of the repo and `gh issue view {{N}}`. Change only what is necessary for issue #{{N}}. Other sessions work in parallel in other areas. Do not touch those areas.
- Before you open the PR, list the error branches and the state branches that your PR creates (return, quarantine, discard, retry, fallback). Make sure that each branch has at least one test in `tests/`. If a branch has no test, write the branch and the reason in the PR body.
- Before you open the PR, run each new test and each changed test:
  - Run the test in two environments: the session environment and a clean environment (`env -i HOME="$(mktemp -d)" PATH="$PATH" LANG=C.UTF-8 bash tests/<x>.test.sh`). If the results are different, the test depends on the environment. Correct the test, not the environment.
  - If the test starts a background process (server, receiver, database), run the test 3 times in sequence. All 3 runs must be green (`(for i in 1 2 3; do bash tests/<x>.test.sh || { echo "falhou na execução $i" >&2; exit 1; }; done)`). `|| break` would exit with 0 even with a failure. If a test stays unstable, write the case and the error in the PR body.
  - If the test runs a host script (`scripts/oute` and similar scripts), remove the real credentials from the environment. These are the credentials that the script would use (`OCI_S3_*`, `GH_TOKEN`, `AGENT_STUDIO_*`…).
  - If the PR changes `tests/*.test.sh` or `tests/lib/`, also run `bash tests/check-lib.test.sh` in the session environment and in the clean environment. Say in the PR body that you ran it. It is the lint of `check` (#285), and a failure there is a failure of the PR (#401). Also run `bash tests/parallel-lib.test.sh` in the session environment and in the clean environment. This run examines the tests that start background services. Say in the PR body that you ran it.
  - If the test proves a criterion, run the test against the code of `main`. To do this, use the tests of the branch with the code of the base (`git worktree add` of `origin/main` + `git checkout <branch> -- <testes>`), or undo the correction. The case must fail. In the PR body, say which cases failed in this way. A criterion does not get `[x]` if its proof does not fail without the correction (`oute-aidlc-qa-pr-audit`, step 6).
- A new test or a changed test must not depend on a value that changes at each run:
  - **Clock:** Keep a relative date or a relative age away from the limit that the code examines, or set the clock to a fixed value. Do not use the exact limit. Example: the code refuses `age > 7` days → use cases with 6 days and with 9 days, not "now − 8 days".
  - **Random name:** The text that the test looks for in the output must not match a part of a `mktemp` path or of a different random name. This rule also applies to the text that the test says is not in the output. Compare the full name. Example: `! grep -q 'b1'` fails with `/tmp/tmp.Xb1k…`. Use `! grep -qF "$SP/proj-b1"` (or `grep -qx`).
- **In a test and in a script, `rm` with a variable uses `"${VAR:?}"/…` or a literal path.** This prevents the permission prompt. Example: `rm -f "${FAKE:?}"/*.json`. Without this protection, Claude Code asks for permission. If there is no answer, Claude Code denies the command in ~1 min 35 s (#358).
- Sometimes you want to write in a doc, an ADR or a PR body that a value, command, variable or file "was removed", "is no longer emitted" or "is no longer used". Before you write this, run `git grep -n -e '<termo>'` on the full repo, from the root and without a folder filter. In the PR body, cite the command and the result. The result is the empty output, or each occurrence that stays and the reason why it stays. If a live occurrence exists in code, the statement is not valid. Write what changed (which emitter stopped and which emitter continues).
